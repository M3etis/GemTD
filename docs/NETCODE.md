# Сетевой режим «Гонка»

## Модель

- **Транспорт:** высокоуровневый мультиплеер Godot + `ENetMultiplayerPeer`, порт по умолчанию 7777. Хост — сервер (peer id 1) и одновременно игрок.
- **Симуляция:** каждый игрок считает своё поле сам — `GameSim` детерминирован. По сети идут только:
  - команды игрока (`place`, `keep`, `forge`, `merge_special`, `make_slate`, `move_slate`, `combine_slates`, `sell_slate`, `move_tower`, `polish`, `give_gold`, … — те же, что пишутся в реплей);
  - такты `hb` (текущий тик) 10 раз в секунду;
  - фаза раунда `phase`, готовность `ready`;
  - контрольная сумма после каждой волны `cs`;
  - итог `over`.
- **Реплики соперников:** у каждого клиента для каждого соперника есть `Replica` (`net/replica.gd`) — копия его `GameSim`. Она применяет команды строго на их тиках и не шагает дальше последнего полученного такта. Поэтому реплика совпадает с оригиналом бит в бит, а наблюдение за чужим полем — это просто показ реплики.
- **Хост управляет таймингом** (`net/race_session.gd`):
  - Волна N открывается одновременно у всех (`begin_wave`), когда все активные игроки готовы.
  - Если в настройках задан таймер раунда, он стартует, когда все дошли до строительства раунда. По истечении хост рассылает `force_build`, и клиент достраивает своё поле детерминированно (командами, реплики их получают).
  - Скорость матча и пауза — только у хоста (не больше трёх пауз за матч). Клиент видит текущую скорость. `RaceSession.speed` / `paused` помнят последнюю команду: если она пришла, пока сцена грузилась, контроллер применит её при создании.
- **Наблюдение:** игрок, открывший чужое поле, шлёт `watch {target, on}`. Хост пересылает его всем, а реагирует только `target`: сообщение и значок в панели игроков (`RaceSession.watchers`).
- **Золото:** в панели игроков видно золото каждого — из реплики. Передача — команда отправителя `give_gold {to, amount}`. Получатель, увидев её среди команд соперника, зачисляет золото своей командой `receive_gold {from, amount}` в следующем кадре (`RaceSession._process`). Обе команды пишутся в реплеи и доходят до реплик, поэтому поля остаются детерминированными.
- **Выбывание:** выбывший (или прошедший все волны) шлёт `over` с итогом и дальше в раундах не участвует: хост открывает волны по готовности оставшихся. У выбывшего — экран продолжения (`RaceOutPanel`: таблица игроков, «Наблюдать: …», «Остаться на своём поле», «Меню», «Выйти из матча»); наблюдение — показ реплики, как и раньше. Выход хоста завершает матч у всех, поэтому хосту кнопка выхода показывает предупреждение.
- **Бесконечная гонка:** в лобби число волн «∞» (`NetProtocol.ENDLESS_WAVES` = 0) даёт в конфигурации матча `max_waves: 0, endless: true`. Поля и реплики создаются с `endless`: победы по волнам нет, после 62-й волны состав идёт по кругу (`GameData.wave_template`), сила растёт за круг. Матч кончается, когда выбыли все; первое место — у продержавшегося дольше (порядок мест тот же).
- **Конец матча:** когда все выбыли или прошли все волны, хост рассылает `end` с таблицей мест. Порядок мест — `NetProtocol.standings`: победа → пройденные волны → жизни → очки → время боя.

## Проверки

- **Рукопожатие:** версия протокола, версия игры и хеш данных баланса. При несовпадении — понятная ошибка, клиент отключается.
- **Сообщения:** каждое сообщение проверяется по типам полей (`NetProtocol.valid_command` / `valid_match_msg` / `valid_control`) у хоста и у получателя.
- **Рассинхрон:** контрольная сумма волны от владельца сравнивается с суммой его реплики. При расхождении игрок видит предупреждение.
- **Итоговая проверка:** в конце матча реплики доигрываются до финального тика владельца, их контрольная сумма сравнивается с итогом игрока (колонка «Проверка» в итогах матча).

## Лобби и поиск

- **LAN-поиск:** хост раз в секунду рассылает UDP-маячок на 255.255.255.255:7778 с именем, числом игроков и версией. Клиент слушает порт 7778.
- **Два экземпляра на одном компьютере:** второй экземпляр не сможет занять порт 7778 и покажет подсказку — подключайтесь по IP `127.0.0.1`.
- **Комната:** хост выбирает сложность, seed (случайный / дня / свой), число волн (20, 42, 62 или ∞; автотест может задать любое `--waves=N`), таймер раунда и «честные камни» (одинаковые роллы у всех). Есть чат с эмодзи, кнопка «Готов», удаление игрока.
- **Чат:** клиент шлёт текст хосту (`_c_chat`), хост пересылает его всем с именем и цветом отправителя (`_h_chat`). Текст — одна строка до `NetProtocol.CHAT_MAX` (160) символов, его чистят и отправитель, и хост. История — последние `CHAT_HISTORY` (50) сообщений в `Net.chat_log`: её показывают лобби и матч, после выхода она стирается. В матче чат — `ChatPanel` на своём слое поверх окон: Enter открывает, Enter отправляет, Esc закрывает.
- **Отключение:**
  - клиент выбывает со своим текущим результатом: у остальных в журнале «вышел», в итогах — пометка «вышел»;
  - если ушёл хост — матч завершается у всех с итогами по последнему известному состоянию. Клиент видит сообщение «Хост вышел — матч завершён», хост в итогах помечен «вышел».
- **Таймаут соединения:** 30 с без подтверждений (жёсткий предел 60 с) вместо стандартных 5 с ENet (`Net.PEER_TIMEOUT_*`). Пока грузится сцена матча (на слабом Mac без кэша шейдеров — секунды), главный поток не опрашивает ENet. С таймаутом 5 с соединение рвалось на старте: хост видел «игрок выбыл», а клиент — «Победа!». Корректный выход шлёт disconnect сразу, поэтому длинный таймаут заметен только при падении игры или обрыве сети.

## macOS

- **Брандмауэр:** при первом создании игры macOS может спросить, разрешить ли Godot или игре принимать входящие соединения. Нужно разрешить, иначе к хосту не подключиться.
- **Локальная сеть:** на macOS 15+ поиск игр в LAN требует разрешения «Локальная сеть» (Системные настройки → Конфиденциальность и безопасность → Локальная сеть). Для собранного `.app` в экспорт-пресет добавляется `NSLocalNetworkUsageDescription` (этап 7).

## Автотест

```bash
tools/mp_selftest.sh 5
```

Запускает два headless-процесса с ботами (хост и клиент на 127.0.0.1), матч на 5 волн. Оба процесса должны напечатать `MP-OK`: итоговая таблица получена, собственный реплей пересимулирован без расхождений, реплика соперника совпала с его итогом.

Долгая загрузка сцены матча у одного из игроков:

```bash
HOST_STALL=12 tools/mp_selftest.sh 2
```

```bash
GUEST_STALL=12 tools/mp_selftest.sh 2
```

Флаг `--load-stall=<секунды>` замораживает главный поток в `_ready` игровой сцены. Соединение должно пережить заморозку, и оба процесса должны напечатать `MP-OK`. С таймаутом ENet по умолчанию (5 с) клиент получал `#1` и `MP-FAIL`.

Без сокетов то же проверяет `tests/integration/test_replica.gd`: реплика, получающая команды и такты пачками разного размера, совпадает с оригиналом по каждой волне.

## Вне первой итерации

В игре этого нет и в интерфейсе это не показывается:

- кооператив на общем поле;
- переподключение после обрыва;
- игра через интернет без проброса порта (relay / WebRTC);
- «давление» на соперников;
- режим «Призрак» (гонка с реплеем своего лучшего забега). Реплеи для него уже есть, сам режим отложен.
