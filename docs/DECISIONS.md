# Журнал решений

Формат: решение → причина. Новые записи — внизу раздела этапа.

## Этап 0–1

1. **Корень проекта Godot = корень репозитория** (а не подпапка `gem_td/`) → команды из README работают как `godot --path .`, без лишнего уровня вложенности.
2. **Godot 4.7.2, Forward+ на Metal** (`rendering_device/driver.macos="metal"`) → нативный рендер Apple Silicon без MoltenVK; Vulkan остаётся запасным драйвером.
3. **Тик симуляции 30 Гц** (`economy.json → sim.tick_rate`) → достаточно для 300+ врагов в GDScript; скорость 2×/4× = больше тиков за кадр, визуал интерполируется.
4. **Свой ГПСЧ xoshiro128\*\* и свои хеши (FNV-1a, murmur3 fmix)** с умножением через `HashUtil.mul32` → не зависим от реализации `randi()`/`String.hash()` между версиями движка и не ловим переполнение int64.
5. **Ролл камня = `fork("draft", раунд, слот)`** → одинаковые камни при одинаковом seed независимо от позиции и боя; основа «честных камней» в мультиплеере.
6. **Граница детерминизма: одна сборка + одна архитектура CPU** (float — double). Мультиплеер (этап 3) обязан сверять версию игры и хеш данных при подключении.
7. **Команды — словари `{type, …, tick}`** → без лишних классов сериализуются в JSON реплея; `GameSim.apply()` — единственная точка входа для действий игрока и бота.
8. **`CombatSystem` не хранит ссылку на `GameSim` между вызовами** → нет цикла RefCounted и утечки памяти при каждом новом забеге.
9. **UI собирается кодом через фабрику `Ui` + `ThemeBuilder` из `UiTokens`**, сцены `.tscn` — тонкие корни. Так все экраны гарантированно используют одни токены, а агенту проще поддерживать единый стиль.
10. **Шрифты Inter + Cormorant (OFL, с кириллицей)**; цифры — Inter с `tnum` (табличные), чтобы счётчики не «прыгали».
11. **Камера: перспектива FOV 34°, наклон 57°, кадр сдвинут влево** → поле целиком помещается в свободную область между верхней панелью, правой панелью волны и нижней панелью фазы (проверено кликами по всем зонам).
12. **5 уровней качества и 9 уровней удачи** — таблица шансов Gem TD+ 1.5.4 (см. PROMPT.md §5.5).
13. **Upgrade Quality реализован уже на этапе 1** (по плану — этап 2) → без него золоту некуда тратиться и MVP не проверяет экономику.
14. **Поле 32×24 целиком проходимо, края = границы поля**; вокруг каждой точки маршрута зона 3×3 без строительства; диагональные шаги только без срезания углов → лабиринт строится «стенами» без обходных щелей.
15. **Летающие идут по прямым между точками маршрута на высоте 1.05** → видно, что лабиринт на них не действует.
16. **Снаряды самонаводящиеся, урон считается при попадании; молния сапфира мгновенная; яд игнорирует значение брони, но учитывает матрицу урона.**
17. **Звук: событие = папка, 4 источника по приоритету** (`--audio-dir`, папка рядом с `.app`, пак в `user://sound_packs/<пак>`, встроенный `res://audio`). Зацикливание реализовано перезапуском по `finished` → работает с любым форматом без настроек импорта.
18. **Звуки по умолчанию — процедурные WAV** (`tools/sfx_generator.gd`), а не скачанные CC0 → нет внешних зависимостей и лицензионных рисков; заменяются без пересборки.
19. **Лидерборд: категории «Классика», «Скорость», «Seed дня» уже на этапе 1** — данные для них есть; «Испытание урона» и «Гонка» появятся с соответствующими режимами. Проверка результата — ресимуляция реплея в `WorkerThreadPool`.
20. **Автопрогоны бота и скриншоты пишут результаты в `user://dev/`** → таблица лидеров игрока не засоряется.
21. **Язык по умолчанию = основной язык системы** (en для `en_KZ`); переключение в Настройки → Язык, для тестов — `--locale=ru`.
22. **Собственный тест-раннер вместо GUT** → нет внешней зависимости; `godot --headless --path . -s res://tests/run_all.gd`.
23. **Проверка компиляции всех скриптов с автозагрузками** — `--check-scripts` в boot-сцене (режим `--check-only -s` не видит автозагрузки и даёт ложные ошибки).

## Этап 2

24. **Компоненты рецепта — точный тип и качество**, специальные башни компонентами не бывают. Если гем подходит под несколько рецептов, игроку предлагаются все варианты.
25. **Сплав из кандидата раунда** берёт недостающие части сначала из других кандидатов (они всё равно станут стенами), затем из башен на поле. **Сплав из башни на поле** использует только башни — кандидаты текущего раунда не трогает, иначе нарушается правило «один гем за раунд».
26. **Поглощённые башни превращаются в стены**, а не исчезают → лабиринт после сплава не меняется.
27. **L2 спец-башни — за золото в любой фазе строительства; L3 — золото + гем-компонент из выбора текущего раунда** (вместо Keep; все кандидаты этого раунда становятся стенами). Так у редких гемов IV–V появляется альтернативное применение.
28. **Продажа: башня → стена**, возврат = (база по качеству/ценности спец-башни + вложенное золото) × 0.6. Разрушение стены и покупка жизни — с растущей ценой (`economy.json`), жизни покупаются только до стартового значения.
29. **MVP**: башня с наибольшим уроном за волну получает стак (+4 % урона, до 10); на 10 стаках — аура +15 % урона соседям в радиусе 2. Значения в `economy.json → mvp`.
30. **Ауры не суммируются от одинаковых источников**: берётся максимум опаловой ауры скорости и максимум ауры Маяк-Линзы; разные источники складываются.
31. **Сохранение = лог команд + seed** (как реплей), загрузка — точная ресимуляция до сохранённого тика с проверкой контрольной суммы. Отдельный «снимок состояния» не делался: он дублировал бы логику и мог бы разойтись с реплеем. Цена — загрузка 42 волн займёт несколько секунд (проверим на этапе 4).
32. **Автосейв в начале каждого раунда**, удаляется после окончания забега; ручные слоты — 3, только в фазе строительства. Автопрогоны и скриншоты пишут сейвы и настройки в `user://dev/`.
33. **Если на поле собран рецепт, автостарт волны не запускается** — игрок сам решает, сплавлять ли до волны.
34. **Логика сцены разделена**: `GamePresenter` (звук, частицы, журнал), `ChoiceLogic` (кнопки выбора, подсказки карточек, доступные сплавы), `game.gd` (цикл, ввод, команды, HUD) — чтобы файлы оставались обозримыми.
35. **Переход между сценами во время анимации не теряется**, а ставится в очередь (найдено сквозной проверкой загрузки сейва).

## Этап 3

36. **Мультиплеер «Гонка» = независимые детерминированные поля + реплики**, а не синхронизация состояния. По сети идут только команды и такты (десятки байт), а наблюдение за соперником и проверка результата получаются бесплатно. Подробно — `docs/NETCODE.md`.
37. **Хост пересылает все сообщения** (звезда), клиенты напрямую не общаются → работает через один проброшенный порт.
38. **Раунды синхронны по старту волны**, но игрок, раньше закончивший волну, может строить следующий раунд сразу. Таймер раунда стартует, когда все дошли до строительства.
39. **Таймер раунда достраивает поле ботом** (`maze`, seed игрока + раунд) — детерминированно и обычными командами, поэтому реплики не расходятся.
40. **Места в гонке:** победа → волны → жизни → очки → время боя. Вышедший игрок ранжируется по последнему состоянию его реплики.
41. **Скорость и пауза в матче — только у хоста**; меню паузы у игрока симуляцию не останавливает.
42. **Записи «Гонки» — отдельная категория лидерборда** (место, число игроков, соперники, реплей своего поля); в «Классику» и «Скорость» они не попадают.
43. **Импорт результатов недоверенный:** из файла берутся только имя, дата и метаданные; очки, волны, урон пересчитываются пересимуляцией реплея. Подделка не проходит (`tests/integration/test_record_io.gd`).
44. **Просмотр реплея — режим игровой сцены**: команды применяются в свой тик, перемотка к волне — быстрая пересимуляция до команды `start_wave` этой волны.
45. **В headless-режиме звук выключен**: фиктивный аудиодрайвер не освобождает потоки, а ботам и автотестам звук не нужен.
46. **Режим «Призрак» не сделан** (по PROMPT.md — «если останется время»); описан в `NETCODE.md` как следующий шаг.

47. **Трейты — данные + один модуль логики.** Параметры в `data/traits.json`, поведение в `sim/enemy_traits.gd`. «Ударные» трейты (Уклонение, Отражение, Закалка, Панцирь) срабатывают только на прямые попадания; урон со временем, ауры и лужи их обходят — это и есть контрплей из спецификации.
48. **Покров:** невидимого врага нельзя выбрать целью, но площадной урон по нему проходит. Обнаружение — Opal (радиус 3–5) и Beacon Lens L3; враг остаётся видимым 2.5 с после выхода из радиуса и 1.5 с после любого урона. Покров есть только у наземных волн (15, 19, 31): на прямой воздушной линии контрплея почти нет — balance_sim показывал −4…−9 жизней за такую волну у всех стратегий.
49. **Эфирность — иммунитет к physical без смены типа брони.** Иначе по матрице ослабел бы nature, а контрплей по спецификации — arcane, fire, nature.
50. **Финальный босс без регенерации.** Фазы по спецификации: щит (15 % HP) → ярость (×1.4 скорости) → призыв наземного и воздушного эскорта. Регенерация в ярости на лабиринте длиной 450+ клеток полностью отменяла урон между кластерами башен; бой длился 8–10 минут.
51. **Боссы быстрее рядовых по отношению к длине лабиринта** (1.3–1.8 клетки/с): иначе босс 42-й волны шёл по максимальному лабиринту больше 5 минут.
52. **Испытание урона — режим поверх фазы COMBAT** (флаг `damage_test`), запускается командой `start_damage_test` и попадает в реплей. Время испытания не входит в метрику «Скорость». Колосс — неуязвимый «босс» с HP по формуле 42-й волны (от него считается процентный урон Titanbane); дойдя до конца пути, он начинает круг заново.
53. **Запись лидерборда после испытания обновляется, а не дублируется:** тот же id, новый реплей, повторная проверка ресимуляцией. Одна строка видна в «Классике» и в «Испытании урона».
54. **Seed дня:** в таблицу идёт лучшая попытка профиля за день на каждой сложности (остальные попытки хранятся, но не показываются).
55. **balance_sim — отдельные процессы Godot, а не потоки.** В потоках одного процесса создание объектов упирается в общую блокировку движка: прогон шёл в 9 раз медленнее.
56. **Стратегии бота — профили весов в коде** (`BotPlayer.PROFILES`). Это не баланс игры, а модель игрока; баланс игры — только в `data/`.
57. **Бот покупает жизни, когда остаётся золото сверх резерва.** Без этого боты проигрывали поздние волны с 3–4 тыс. неистраченного золота. Покупка жизни есть в спецификации, и живой игрок поступит так же.
58. **Время спавна округляется до 0.1 мс** — совпадающие времена разных групп равны точно, порядок спавна стабилен.
59. **Сообщения матча не теряются при старте.** Пока сцена матча грузится, `Net` копит входящие сообщения и отдаёт их `RaceSession` при подписке. Без этого первые команды быстрого соперника (камни 1-го раунда на тике 0) терялись, и реплика расходилась.
60. **Критерий баланса этапа 4:** на Normal каждая из пяти стратегий бота (maze, specials, damage, control, antiair; 50 seed) побеждает в 25–90 % забегов. Ни одна не доминирует (> 90 %) и ни одна не бесполезна (< 25 %). Разрыв между лучшей и худшей — не больше 35 п. п. Easy: у всех стратегий ≥ 85 %. Hard рассчитан на игроков сильнее бота (бот не ломает стены, не продаёт башни и не управляет приоритетом целей); требование для Hard — у каждой стратегии есть победы.

61. **Пресеты графики — в коде** (`view/graphics.gd`): это настройки рендера, а не баланс игры. Low / Medium / High / Ultra управляют glow, SSAO, SSIL, туманом, MSAA/TAA/FXAA, масштабом рендера, тенями, плотностью частиц, светом башен и преломлением в кристаллах. `--preset=` в командной строке перекрывает настройку (замеры, скриншоты).
62. **Частицы — пул `GPUParticles3D`** (64 малых и 16 больших одноразовых излучателей, 4 вихря) с общим аддитивным спрайтом. Постоянные излучатели — искры у гемов V, «дыхание» спец-башен, вихрь портала, пыль над ареной. Плотность умножается на пресет. Для billboard-частиц обязательно `billboard_keep_scale`, иначе масштаб частицы игнорируется и все частицы рисуются размером 1 м.
63. **Преломление в кристаллах — только на Medium и выше.** Чтение экранной текстуры переводит материал в прозрачный проход (кристаллы перестают отбрасывать тень), поэтому на Low используется непрозрачный вариант шейдера. Общее ядро — `fx/shaders/gem_core.gdshaderinc`, варианты собираются через `#define`.
64. **Ударные волны с искажением** — плоскость на земле, сдвигающая экранную текстуру по кольцу (Combine, Forge, фазы и смерть босса, ударная волна Quake Heart, вспышка Cinder Crown). С «уменьшить анимации» — обычное кольцо без искажения.
65. **Тряска камеры только для боссов и крупных взрывов**, отдельный переключатель. Кинематографичный наезд при Forge (0.9 с) — тоже отдельный переключатель; «уменьшить анимации» выключает оба.
66. **Руны статусов — глиф на тёмной подложке** (обычное смешивание, без теста глубины): аддитивные иконки терялись на светлых врагах.
67. **Тени летающих — пятна-декали** (MultiMesh под каждым летающим врагом). Они читаются и на Low без теневых карт; на High+ дополнительно работает обычная тень солнца.
68. **Урон со временем (яд, лужи) начисляется раз в 3 тика** (`economy.sim.dot_ticks`) тем же суммарным уроном. Тик при 300 врагах: 2.2 → 1.5 мс. Ещё −0.2 мс дали шаг трейтов только у врагов, которым он нужен, и переиспользование корзин пространственного хеша.
69. **Запасной рендер — Compatibility (OpenGL).** `rendering_device/fallback_to_opengl3` в проекте; SSAO, SSIL, TAA и FSR в этом режиме отключаются автоматически. Проверка: `--rendering-method gl_compatibility`.
70. **Прогрев шейдеров эффектов** при загрузке арены: каждый тип эффекта один раз рисуется невидимым. Иначе первый сплав или взрыв давал рывок из-за компиляции.
71. **Стресс-тест — настоящая игровая сцена в режиме `stress`** (HUD, звук, все эффекты), а не отдельная сборка из рендереров. 60 башен ставятся напрямую (это стенд замера, а не забег), убыль врагов пополняется до 300.

72. **Музыка процедурная** (`tools/music_synth.gd`): тёмный эмбиент в ре миноре, 22 кГц моно (4 МБ на 6 треков). Зацикленные треки рендерятся «по кругу» — хвосты нот за концом буфера переносятся в начало, стык петли не слышен. Петля для WAV включается в коде (`loop_mode`), для своих OGG/MP3 — флагом `loop`.
73. **Музыкальные состояния следуют за своим полем** (события своей симуляции): строительство → бой или босс → строительство, победа и поражение — разовые треки. Наблюдение за соперником в «Гонке» музыку не переключает.
74. **Панорама — две шины с `AudioEffectPanner`** (`SFX_L` / `SFX_R`, ±0.45) вместо позиционных 3D-плееров: дёшево, работает с пулом голосов и не меняет громкость по расстоянию до камеры.
75. **Обучение — заданное выпадение гемов** (`GameSim.config.draft_overrides`), а не отдельный сценарий: обучение идёт настоящей симуляцией и командами игрока. Реплей таких настроек не хранит, поэтому забег обучения не отправляется в таблицу лидеров.
76. **Подсказки — один раз за всё время** (`general.hints_seen`) и короткими уведомлениями внизу, без модальных окон: они не прерывают игру.
77. **Палитра для дальтоников — одна, Okabe–Ito**: она различима при всех частых видах дальтонизма, отдельные режимы протанопии/дейтеранопии не нужны. Кроме цвета, у каждого гема свой силуэт, у типа урона — значок.
78. **Масштаб текста меняет общую тему на месте** (размеры шрифтов от исходных), поэтому все открытые экраны обновляются сразу. Масштаб интерфейса — `content_scale_factor` окна.
79. **Tab обрабатывается в `_input` игровой сцены**: иначе его забирает навигация фокуса интерфейса.
80. **Автофокус окон предпочитает главную кнопку**: если первым фокус получит поле ввода, Space и Enter начнут печатать вместо действия.
81. **Замедление времени (редкий гем) живёт в автозагрузке `Game`**: таймер возврата не теряется при смене сцены, а переход между сценами всегда возвращает нормальную скорость.
82. **Лидерборд при выходе дожидается фоновых проверок реплеев**: поток проверки не должен пережить объект (найдено скриншот-прогоном, падение при выходе сразу после забега).
83. **Подтверждения можно выключить** (Настройки → Игра): `Modal.confirm` сразу выполняет действие.


## Этап 7 (релиз)

98. **Светлое поле** (по просьбе игрока: тёмные стены сливались с тёмным полем).
    - Поле — светлый матовый камень с лёгкой собственной подсветкой: сцена освещена холодным синим светом, без подсветки камень уходит в серо-синий.
    - Стены остаются тёмным обсидианом.
    - Путь, круги радиуса, лужи и призрак камня переведены со сложения света (`blend_add`) на обычное смешивание с насыщенными цветами: прибавленный свет на светлом камне не виден. Слишком светлые цвета колец (алмаз, аметист) шейдер затемняет.
    - Снаряды, вспышки и молнии остаются аддитивными — это светящаяся энергия.
    - Враги стали насыщеннее и темнее, их ободок цветной.
    - Где нет теней солнца (Low, Compatibility), пятна теней рисуются и под наземными врагами. Цена — около 3 FPS на Low (136 → 133 в стресс-тесте).

99. **Отступление от §3: модели врагов взяты у Quaternius (CC0 1.0)**, по решению владельца проекта (27.10.2026). Каменный Страж остаётся процедурным.
    - **Что разрешает §3.** Только сторонние звуки и текстуры под CC0 и шрифты под OFL, меши — собственные.
    - **Источник.** 15 моделей с poly.pizza, у каждой на странице «CC0 1.0», автор Quaternius. С 28.08.2026 на quaternius.com действует своя лицензия QAL, но по её тексту она не применяется задним числом к уже полученному. Подтверждение и ссылки — в `assets/models/enemies/src/LICENSE.txt`, список файлов — в `assets/LICENSES.md` и в игре («Авторы»).
    - **Запекание.** Исходные GLB лежат в `src/` с `.gdignore`: они в репозитории для перезапекания, но не импортируются и не входят в сборку. В игре — статичные меши из `tools/bake_enemy_models.gd`.
      - Кадр анимации шага или полёта.
      - Поворот «вперёд» на +X.
      - Основание в y = 0, ширина 1,7.
      - Цвета материалов переходят в вершины: затемнение — в `COLOR`, осветление (белки глаз, брюхо) — в `UV2.x`. Шейдер врага по-прежнему тонирует модель цветом архетипа. Основной цвет выбирается по площади: глаза — плотные сферы и по числу треугольников «побеждали» тело.
    - **Почему не скелетная анимация.** Врагов до 300 на поле, а MultiMesh скелетную анимацию не поддерживает. Покачивание делает шейдер, как и раньше.
    - **Запекание только с окном.** В headless-режиме фиктивный рендер-сервер не создаёт скелет, и `bake_mesh_from_current_skeleton_pose` отказывается работать. Позу нужно ставить после регистрации скина (через два кадра), иначе она сбрасывается к исходной.
    - **Упрощение** — `ImporterMesh.generate_lods`, до 1200 треугольников у обычных врагов и 1500 у боссов. При бюджете 700 пропадали глаза. Ключ меша — по архетипу (`MeshFactory.enemy_model`), данные не менялись, поэтому хеш баланса, сейвы и рекорды совместимы.
    - **Цена.** Стресс-тест на 300 врагов: High 103 → 95 FPS, 1 % low почти без изменений; на Low разницы нет.
    - **Масштаб по ширине** (размах лап, крыльев, хвоста) делает тонкие модели мелкими. Поправки: паук ×1,5, раптор ×1,3, летучая мышь ×1,2, демон и йети ×1,3. Летучая мышь запечена на 0,75 взмаха — с раскрытыми крыльями, иначе сверху она выглядит чёрточкой.

100. **Визуальный ремейк «Обсидиановая сокровищница»: готовые ассеты вместо процедурных** (03.11.2026, по брифу владельца; стиль, палитра и правила — `ART_DIRECTION.md`, требования — `ASSET_REQUIREMENTS.md`, кандидаты — `ASSET_CANDIDATES.md`).
    - **Отступление от §3.** Кроме CC0 и OFL разрешены CC BY (атрибуция в `CREDITS.md` и на экране «Авторы») и Fab Standard License (без публикации сырых файлов). CC BY-SA — только после отдельного согласия.
    - **Цвета гемов в кадре — `UiTokens.ART_GEM`**, а не `data/gems.json`: data целиком входит в хеш данных (сейвы, реплеи, рекорды, сеть). Палитра Okabe–Ito для дальтоников по-прежнему главнее.
    - **Пол** — плиты Tiles139: одна плита на клетку, случайная плита атласа и поворот на клетку (`textureGrad`, чтобы на швах не прыгал мип). Сетка рисуется только в фазе строительства, в бою клетки читаются по швам.
    - **Стены** — скан Poly Haven, упрощённый до ~400 треугольников и «квадратизированный» в плане, чтобы блоки смыкались в стену; материал — Rock035 трипланарно (у процедурных мешей нет UV). Прожилки вспыхивают только при смене пути.
    - **HDRI только для света и отражений** (`ambient_light_source = Sky`): камера под 57° горизонта не видит, фон остаётся своим. Туман сдвинут за поле (56–110 м): камера стоит в ~45 м, прежние 26 м затуманивали само поле.

    - **Исходники ассетов** не в репозитории (`art_src/` в `.gitignore`), их ссылки — в `tools/bake_art_assets.gd`; в репозитории — подготовленные меши и карты.

101. **Враги и боссы — готовые анимированные модели, анимация запечена в VAT** (03.11.2026, пакет «Враги» ремейка; кандидаты C1–C7, C9 из `ASSET_CANDIDATES.md`). Заменяют статичные меши Quaternius из п. 99.
    - **Почему VAT, а не скелеты.** Врагов до 300 на поле, рисуются они MultiMesh'ем, а он скелетную анимацию не поддерживает. `tools/bake_enemy_vat.gd` проигрывает клип ходьбы (полёта) и смерти, запекает позы по кадрам в две RGBA16F-текстуры (позиции; окт-нормаль + окт-касательная), а `fx/shaders/enemy_vat.gdshader` берёт позу по фазе из `INSTANCE_CUSTOM.w` и интерполирует соседние кадры. Боссы идут тем же путём: один конвейер, и сцена по-прежнему не держит скелетов.
    - **Фаза цикла — от пройденного пути** (`EnemyRenderer._advance`): шаг ног совпадает с ходом по полю, оглушённый враг замирает, замедленный перебирает ногами медленнее. Летающие и парящий босс машут по времени. Фаза — только вид: симуляция, реплеи и сеть не затронуты.
    - **Упаковка `INSTANCE_CUSTOM`.** Флаги замедления и яда слились в один канал (`+1` / `+2`), четвёртый отдан фазе клипа: `[0, 1)` — цикл, `[1, 2]` — смерть.
    - **Смерть.** Если у модели есть клип, он играет целиком (до 1,6 с, у боссов до 2,4 с), растворение — в последние 40 %. Без клипа — прежнее растворение за 0,45 с. Длительность смерти — тоже только вид.
    - **Материалы сведены в один PBR-атлас** на модель (treemap по площади поверхности: крупный материал не теряет разрешение из-за глаз и зубов). Один материал — один вызов отрисовки на архетип. Атласы в JPG: в PNG карты боссов весили бы ~130 МБ.
    - **Бюджеты.** Рядовые ≤ 2 300 треугольников, боссы ≤ 6 200 (`tests/unit/test_enemy_vat.gd`). Упрощение — `ImporterMesh.generate_lods` по позе первого кадра: вершины не выдумываются, а выбираются из исходных, поэтому у каждой есть поза во всех кадрах.
    - **Цвет архетипа** — частичная тонировка альбедо по яркости и цветной ободок (fresnel) — по нему враг читается мелким на светлом поле. Тонкие силуэты увеличены (паук ×1,6, мышь ×1,35, раптор ×1,25), подстройки — `ArtKit.ENEMY_LOOK`.
    - **Fab.** Golem и DemonLord2 — Fab Standard License (тир Personal подтверждён владельцем). Сырые файлы не в репозитории и не в сборке отдельно, в игре — только запечённые меши и атласы.
    - **Ретаргет.** У Shadowkin Mage (Заговорённый) нет клипов: ходьба и смерть DemonLord2 переносятся со скелета UE4 на риг Character Creator (мировой поворот кости относительно покоя + выравнивание направлений костей покоя: у источника A-поза). Плащ без костей ретаргета доворачивается вниз, чтобы не торчать назад.
    - **Раскольник и Осколки** — процедурные шестигранные кристаллы на материале обсидиана, прожилки окрашены цветом архетипа; анимация (кольцо спутников, прыжки, разлёт при смерти) считается в том же скрипте и пишется в тот же VAT.
    - **Подводные камни запекания.** Нужно окно (в `--headless` скин не регистрируется). После `seek` нужен кадр движка, иначе все кадры одинаковы. Глаза Bug и Pteran при скиннинге улетают на десятки метров (ошибка привязки в исходниках) — эти меши пропускаются. Экшены `.blend` мыши (2018) в Blender 5 не вычисляются depsgraph'ом, поэтому `tools/blender_export_bat.py` экспортирует ключи F-кривых без семплирования.

102. **Эффекты и интерфейс — пакет «VFX и UI» ремейка** (03.11.2026; кандидаты V1, V2, U1 из `ASSET_CANDIDATES.md`).

Соседние кадры смешиваются, живых флипбуков не больше 24, на пресетах с низкой плотностью частиц часть пропускается.

    - **Портреты врагов в Кодексе** — рендеры VAT-моделей на прозрачном фоне (`tools/art_preview.tscn -- --portraits`).
    - **Чипы карточки драфта переносятся** (`HFlowContainer`): после FS_XS 13 «Магия» + «Земля + воздух» не влезали в колонку, карточка распиралась и наезжала на соседнюю.

    - **Обсидиановый Король** — Armored Guard Knight Rig (DM-913, Sketchfab). Золото лат переведено в тёмную бронзу (`grade`), копьё снято: оно висит на кости у корня и без IK за кистью не пойдёт.
    - **Анимации** Короля и Заговорённого — Walk_Loop и Death01 из Universal Animation Library (Quaternius, CC0, версия без root motion). Кости UAL названы как у Unreal, поэтому карта Shadowkin от DemonLord2 перенеслась почти без изменений. Рыцарь смотрит в −Z, UAL — в +Z: бейкер сам доворачивает источник (`_align_source`: угол по позициям покоя сопоставленных костей, шаг 90°), иначе шаг вперёд лёг бы на модель шагом назад. Пластины доспеха рыцаря (набедренники, наплечники, щитки стоп) сопоставлены с костями конечностей — без этого они застывали бы в позе Idle.
    - **Шаг ходьбы** новых моделей не подбирается на глаз: бейкер замеряет путь за цикл (опорная нога в клипе на месте скользит назад со скоростью хода) и пишет мету `stride`, `ArtKit.enemy_stride` берёт её, если в `ENEMY_LOOK` нет ручного значения. Пёс — 1.67 (на глаз стояло 0.8, бег мелькал вдвое быстрее хода), рыцарь — 0.82, Заговорённый — 0.88. У старых моделей ручные значения оставлены: у четвероногих замер расходится с ними, а их подбирали по виду в игре.
    - **Атласы:** у пса исходник 1K — атлас 1024, а не 2048; у рыцаря нет карты нормалей — плоский атлас нормалей не пишется (шейдер берёт плоскую нормаль сам).

    - Производные файлы Fab удалены из рабочей копии и из истории git (см. §105).

105. **Визуальный стиль и ассеты Fab** (03.11.2026). Вместе с ремейком изменился хеш данных баланса (снос стены дешевле), поэтому сейвы, реплеи и матчи «Гонки» прежних сборок несовместимы: лобби сверяет версию и хеш, реплей — хеш. Первая версия ремейка брала Каменного Стража и Обсидианового Короля с Fab (Golem, DemonLord2); их заменили моделями под CC BY 4.0 до публикации, и в истории репозитория файлов Fab нет — она сведена в один коммит релиза (§126).

106. **Слияние спец-башен и подсказки трекера** (03.11.2026).
    - **Что растёт ×1.75** (выбор автора).
      - Урон — через `TowerState.damage_mult()`: так множитель сам доходит до выстрелов, горения, луж и процентного урона.
      - Сила эффектов — явно в местах применения (`power()`, `scaled_slow()`): ауры Маяка и Знамени, снятие брони, уязвимость, метка, награда и золото идола.
      - Дальность и скорость атаки, радиусы, шансы и длительности прежние. Иначе DPS вырос бы примерно втрое, а дальнобойные башни накрывали бы почти всю карту.
      - Замедление Морозного колодца ×1.75 дало бы 0,79 — враги почти стоят. Поэтому потолок `max_slow` 0,75 (только для слитых, базовые значения не режутся).
    - **Один раз:** слитая башня не сливается снова (выбор автора). Две башни дают одну на 1.75, а не на 2: слияние освобождает клетку, но не даёт чистой силы.
    - **Какая остаётся:** выбранная в панели. Пара — такая же неслитая; если их несколько, берётся сильнейшая (уровень, затем урон). Команда несёт обе клетки, поэтому реплей и сеть однозначны.
    - **Замена в трекере** не автоматическая, а кнопкой: отслеживаемые рецепты — выбор игрока, и они переживают забег. Пока на поле нет ни одного подходящего камня (начало раунда), предлагать нечего, и подсказки нет.

107. **Совместимость — проверками, а не номером** (03.11.2026). Хеш данных менялся по ходу разработки не раз; несовместимость закрыта проверками: лобби сверяет версию игры и хеш данных, реплей и сейв — хеш, рекорды других сборок видны в фильтре «Все версии». Сетевой протокол (`NetProtocol.VERSION`) не менялся: новые команды (`merge_special`, `sell_slate`, `move_tower`, `polish`) до клиента другой сборки не дойдут — его не пустит лобби.

108. **Чат в матче «Гонки»** (03.11.2026).
    - **Сеть не менялась:** чат лобби (`_c_chat` → хост → `_h_chat`) работал и в матче, не было только окна. Протокол тот же.
    - **История в `Net`, а не в окне:** окно матча появляется после загрузки сцены, а комната лобби пересобирается при смене состояния. Если хранить историю в окне, сообщения теряются.
    - **Enter, а не T:** Enter свободен (подтверждение — Space). Перехват — в `_input`, до интерфейса, иначе Enter нажал бы кнопку в фокусе. Пока поле ввода открыто, игра Enter не трогает. Окна паузы, Кодекса и подтверждений Enter не отдают. Итоги матча отдают — в них самое время для «gg».
    - **Свой слой (11) поверх окон:** чат виден и в итогах. Слева вверху свободно, а высокая панель башни, если заходит туда, приглушает закрытую ленту.
    - **Камера:** пока поле ввода в фокусе, `CameraRig.input_enabled` выключен, иначе WASD двигали бы камеру во время набора.

109. **«Гонка»: скорость, наблюдение, золото; сплав на последнем камне** (03.11.2026).
    - **Золото зачисляет сам получатель** командой `receive_gold`, а не отправитель в чужое поле. Каждое поле меняют только команды его владельца. Так реплики соперников и реплеи пересимулируются одинаково, а `give_gold` и `receive_gold` проверяются симуляцией как любые другие команды.
    - **Выбывшему не передать.** Итог выбывшего уже отправлен: изменение золота после финального тика разошлось бы с контрольной суммой, и реплика не прошла бы проверку. Если подарок всё же пришёл после выбывания, он теряется.
    - **Скорость у клиента:** текущая кнопка остаётся активной и подсвеченной, остальные неактивны. Неактивная нажатая кнопка в теме не отличалась бы от ненажатой.
    - **Сплав из панели фазы** — на самом новом компоненте. Игрок только что поставил этот камень и ждёт башню именно там. Выбор любого другого компонента остаётся в панели башни.

110. **Слияние: свои + 0.75 × второй** (03.11.2026, выбор автора; заменяет ×1.75 из §106).
    - **Наследуется уровень, а не множитель.** `merge_level` хранит уровень второй башни на момент слияния. Урон — `L(свой) + inherit × L(унаследованный)` в `refresh_stats`; сила эффектов — `TowerState.strength()` по списку `MERGE_STRENGTH_KEYS`. У двух одинаковых результат тот же (×1.75). У разных уровней — честная сумма: L3 + L1 даёт L3 + 0.75 × L1, а не 1.75 × L3.
    - **Свой уровень — больший, унаследованный — меньший,** независимо от того, какую башню выбрали в панели. Иначе выбор не той башни молча отнимал бы силу.
    - **Прокачка поднимает только свою часть** (выбор автора): унаследованная — это снимок второй башни.
    - **`damage_mult()` больше не содержит слияния:** ауры и MVP умножают уже сложенный урон. У неслитых башен числа бит в бит прежние, контрольная сумма бота не изменилась.

111. **Сплав в любой момент матча** (03.11.2026). В «Гонке» оставленный последний компонент сразу делает игрока «готовым», и хост открывает волну, если готовы все. Раньше сплав был только в фазе строительства — игрок не успевал. Теперь `BuildCommands.forge` закрыт только после проигрыша и в Испытании урона. В бою кандидатов нет: собирают только башни, путь не меняется (GEM → ROCK). Слияние, улучшение и продажа по-прежнему только в строительстве: просили только сплав.

112. **Слейты из Gem TD 3.2** (03.11.2026; набор, размещение и рецепты из гемов раунда — выбор автора).
    - **Источники:** энциклопедия 3.2 (gamersky) — шесть базовых и три составных с рецептами; сводка PTT [BK's] 2008 — числа, Площадной, Урона, Гадюка. Рецепты Площадного и Урона в 3.2 не записаны, они взяты из Gem Tower Defense 2026: Урона — Алмаз III + Опал / Сапфир II; Площадной — Рубин III + Аметист / Топаз II (без Рубина II: пара из двух рубинов путалась бы с «Объединить»).
    - **Сущность — `TowerState` с `slate_id` в отдельном `GameSim.slates`.** `CombatSystem.hit` начисляет слейту урон и убийства, как башне (от этого растут Удерживающий, Урона и Гадюка). Ауры, MVP, детекторы и обезоруживание перебирают только `towers` — слейты их не задевают. Клетка остаётся EMPTY: проходимость A* не меняется, а `can_place` отказывает на слейте.
    - **Клетка слейта открывается** (как в оригинале). Оставлять там стену, а плиту класть в другое место значило бы лишний шаг размещения. Бот выбирает для слейта кандидата, открытие которого меньше всего укорачивает путь, и переносит плиту на путь.
    - **Бой — данными, а не кодом под каждый слейт:** интервал, радиус, all/single, урон и набор эффектов в `slates.json`. Общий `SlateCombat` понимает damage_air, damage_per_kill, damage_per_wave, poison, slow (−1 — до смерти), stun + armor_reduction на время оглушения, spell (у Руин — четыре варианта через `combat_rng`), stack_damage, death_blast, уровни за убийства, ауры aura_speed / aura_damage.
    - **Удары тихие** (`quiet`): плита на земле — ловушка, а не выстрел, она не проходит через уклонение и Отражение. Это и проще для чтения, и ближе к оригиналу.
    - **Баланс.** Стартовые числа из 3.2 давали слабые базовые слейты: фиксированный урон отставал от HP, растущего на ~14 % за волну. Бот, делавший слейт при каждой возможности, выигрывал 12/24 (50 %) против 20/24 у `maze`. Базовым добавлен урон за номер волны (Заклинаний +3, Парящий +4, Удерживающий +10, Замедляющий +8, Жила +4, Площадной +2) и радиусы +0.5. Результат — 16/24. Боту добавлено правило: гем IV–V он оставляет, а не меняет на слейт; слейты он раскладывает и объединяет один раз за раунд. Итог на 48 сидах: `slates` 39/48 (81 %) против `maze` 36/48 (75 %). Слейты — сильный, но не ломающий выбор.
    - **Отдельные ячейки эффектов.** У врага одна ячейка замедления и одна снятия брони: сильнейшее перезаписывает слабое. Поэтому «замедление до смерти» стирал гем Аквамарин II и выше, а −12 Древнего — аура Ржавого обелиска. У врага добавлены `slow_floor` (постоянное замедление) и `timed_shred` (снятие брони на время), действует сильнейшее из ячеек. Очищение (Антимагия) снимает и постоянное замедление.
    - **Клетка под слейтом — в сетке** (`BoardGrid.reserved`): проходима, но не строится, и второй слейт на неё не ляжет. Раньше это проверялось в каждом месте отдельно.

114. **Второй акт: волны 43–62** (04.11.2026).
    - **Боссы — 52 и 62, а не 50 и 60.** Каждая 4-я волна воздушная (44, 48, 52, 56, 60), и в воздушную можно поставить только летающего босса. Небесный Левиафан на 52-й её не ломает; Матка и Король — на 62-й, вне воздушного ряда. Получилось 10/20/30 и 42/52/62 — второй акт повторяет ритм первого со сдвигом.
    - **Король остаётся на 42-й.** Это конец первого акта и прежний полный забег: в «Гонке» есть вариант «42 волны» с финалом на Короле. На 62-й он возвращается с Маткой Роя.
    - **Новых архетипов нет.** Модели врагов — VAT-запечённые ассеты с лицензиями (§104); перекрашенный дубликат выглядел бы той же моделью под другим именем. Разнообразие — из связок трейтов, элиты и смешанных групп.
    - **Поздний рост HP — 1.05, а не 1.14** (`hp_formula.late`, с 42-й волны). Сила доски к концу выходит на плато: качество V и удача IX — потолок, спец-башни — L3, новая башня — одна за раунд. При прежней экспоненте (×13.7 за 20 волн) бот `maze` (seed 1001), прошедший первый акт без потерь, погиб на 44-й, при 1.07 — на 56-й. С 1.05 большинство наземных волн 45–61 проходят почти без утечек, а поражения дают отдельные составы — воздух, 49-я, 58-я; их и правили. Сложность второго акта задают составы, а не голое HP.

Лабиринт не удлиняет воздушный путь, и сила против воздуха растёт медленнее, чем против земли: в первом черновике волна 60 (30 летающих с Отражением и регеном) давала 11 утечек в среднем, 56-я — 6.5.
    - **Без регенерации на элите.** Реген — 2 % от макс. HP в секунду, а элита умножает HP на 2.2: 58-я из элитных Живучих с Панцирем (он снимает яд, режущий реген) была главной волной поражений — у `maze` и `damage` на ней гибли 6–7 забегов из 12. Теперь 58-я — неэлитные Живучие в Панцире и элитные быстрые.
    - **Финал (62):** Матка ×5 выходит на 8-й секунде, Король ×14 — на 22-й. Первый черновик (элитный Король ×16 и Матка ×12) отсекал 60 % дошедших. Со вторым (Король ×18, Матка ×8) бой шёл 400 с: Матка без конца призывала свиту, урон делился, и Король доходил до цитадели с четвертью HP. Сейчас финал отсекает около четверти дошедших.
    - **Боссы первого акта облегчены** — первый акт больше не весь забег, и проходить его надо с запасом на второй.
        - Король на 42-й ×16 → ×12: на нём гибла четверть всех забегов Normal, а теперь это середина игры.
        - Матка Роя на 30-й ×30 → ×26. На этих двух наземных боссах гибла стратегия `antiair`, и разрыв на Normal был 40 п. п. при критерии 35; последний шаг Короля (×13 → ×12) — оттуда же.
        - Небесный Левиафан на 20-й ×12 → ×9: он самый «бинарный» босс (воздушный путь в 4–6 раз короче лабиринта), а на Extreme его утечка — мгновенное поражение.

115. **Баланс сложностей на 62 волнах** (04.11.2026).
    - **Разгон HP** (`difficulty.hp_ramp_waves`): множитель сложности растёт от ×1.0 на первой волне до `hp_mult` к волне ramp + 1. Без него на Hard и Extreme забег решали первые камни: у игрока одна-три башни I, и враги ×1.25–1.8 текли уже на 1–3-й волне (на Extreme — 2 утечки из 10 жизней в среднем на первой волне). Hard — к 13-й волне (×1.15), Extreme — к 41-й (×1.5): ранние боссы на Extreme крепки как на Hard, зато второй акт — самый тяжёлый.
    - **Награда за убийство на Hard и Extreme — ×1.0, а не 0.9 / 0.85.** Меньше золота → позже удача → ниже качество гемов: штраф складывается снежным комом на 62 волнах, и на Hard у трёх стратегий из шести не было ни одной победы. Сложность уровня — в крепости врагов, жизнях и правиле босса; в описании Hard про золото и не говорилось.
    - **Easy — HP ×0.7** (было 0.75): на 62 волнах четыре стратегии побеждали в 83 %.
    - **Extreme: мгновенное поражение от босса — остаётся,** это суть уровня. HP на нём почти не решает: летающий босс 20-й уходит с 30–75 % HP, и ни снижение множителя на 20-й волне с ×1.48 до ×1.24, ни HP Левиафана ×12 → ×9 не уменьшили число поражений `maze` на 20-й (12 seed). Утечка зависит от того, хватает ли на доске урона по воздуху, а его у бота к 20-й волне мало даже в стратегии `antiair` (8 поражений на 20-й из 20). Поэтому Extreme рассчитан на игроков сильнее бота: тех, кто готовит оборону на линии полёта заранее.
    - **Сложность в HUD — в шапке блока волны** («Волна · Сложность Экстрим»), а не отдельным блоком. Отдельный блок добавлял панели 114 px, и при масштабе интерфейса 110 % с текстом 115 % кнопки Кодекса и настроек уходили за край; шапка добавляет около 50 px, и панель помещается (1709 из 1713 px). Подсказка разгона — «100 % → X % к N-й волне», а не «до X %»: так верно и для множителя ниже 1.
    - **Стратегия `slates` — в стандартном наборе balance_sim** (`BotPlayer.BALANCE_STRATEGIES`): слейты — часть игры.

120. **Слейт — отдельный слой, перенос за растущую цену** (05.11.2026).
    - **Строительству слейт не мешает:** камень встаёт на клетку со слейтом (`BoardGrid.is_buildable` больше не смотрит на `reserved`), слейт работает дальше, над камнем, стеной или башней светится его значок. Второй слейт в ту же клетку не положить (`can_hold_slate`), и из камня, стоящего на слейте, слейт не сделать — только из другого камня рецепта (новый лёг бы в ту же клетку).
    - **Клик:** башня и стена выбираются раньше слейта под ними (слейт — кнопкой «Под ней слейт: …» в их панели); при расстановке клик по клетке со слейтом ставит камень.
    - **Продажа слейта — своя команда `sell_slate`.** Команды адресуют объект клеткой, а под башней теперь может лежать слейт: «Продать» в панели такого слейта продавало бы башню. `sell` в клетке без башни по-прежнему продаёт слейт (старые реплеи и бот).
    - **Перенос — сколько угодно раз, каждый дороже:** 5 + 5 × (сделанные переносы всех слейтов) (`economy.slate_move`). Общий счётчик, а не свой у каждого слейта: иначе дешёвые первые переносы новых слейтов обходили бы рост цены. Класть можно на любую клетку без слейта — на путь, под стену или башню.

121. **Перенос башни** (05.11.2026).
    - На стену или башню — обмен местами (лабиринт тот же), на пустую клетку — переезд с пересчётом пути (перекрыть путь нельзя, зоны у точек маршрута закрыты, как для камней). Без этого «перенос» превращался бы в бесплатную стену: переезд на пустую клетку освобождает старую.
    - Цена 10 + 10 × (сделанные переносы), только в строительстве. Слейт под башней остаётся на месте — он отдельный слой.
    - Неудачный клик (перекроет путь, не хватает золота) оставляет режим переноса включённым — можно сразу выбрать другую клетку.
    - **Подсветка цели переноса** пересчитывается, только когда меняется клетка под курсором или поле (любая успешная команда): проверка переноса на пустую клетку — поиск пути.
    - **В реплее** кнопки панели башни, слейта и стены выключены (кроме «закрыть» и «Под ней слейт»): команды в реплее не применяются, а режим переноса там не завершить.

122. **Огранка — сток золота для поздней игры** (05.11.2026).
    - **Проблема:** в бот-прогонах удача выходит на максимум к 30-й волне, а к финалу копится 3–4 тыс. золота (бот покупает жизни, человек — даже их не всегда).
    - **Решение — растущая цена при постоянной пользе:** +3 % урона за уровень, до 10, цена 40 × 1.55ⁿ (≈ 5.7 тыс. за всё). Польза линейна, цена — геометрическая, поэтому золото превращается в силу логарифмически: удвоение запаса даёт лишь пару уровней. Потолок +30 % — меньше 10 стаков MVP (+40 %), и это урон одной башни, а не всего поля.
    - **Отвергнуто:** глобальный бафф всех башен (масштабируется с размером поля — сильнее, чем кажется), лишний камень раунда (ломает ритм «один гем за раунд»), реролл гемов за золото (сильный и непрозрачный для баланса — с запасом золота перекатывали бы до пары V), «косметика» (не решает проблему).
    - **Только башням, наносящим урон** (`TowerState.deals_damage`): Маяк-Линза и Боевое знамя (attack «none») и Морозный Колодец (замедление) от `damage_mult()` ничего не получают, и золото уходило бы впустую.
    - **Сплав сохраняет огранку:** вложенное золото башен-компонентов переходит в спец-башню (продажа вернёт 60 %), уровень — больший из компонентов, как при слиянии (у башни поддержки — только золото). Пока огранки не было, у гемов вложенного золота не было, и потерять его при сплаве было нельзя.
    - **Бот по умолчанию огранку не использует** (`BotPlayer.use_polish`): эталонные прогоны и контрольные суммы прежние, а `balance_sim --polish` меряет, насколько она сдвигает баланс (итог — §124).
