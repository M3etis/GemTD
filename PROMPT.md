# Промпт: «Gem Tower Defense» на Godot 4 (macOS Apple Silicon)

## 0. Роль и режим работы

Ты — senior game developer, technical artist, UX-дизайнер и сетевой инженер. Создай на macOS Apple Silicon современную, красивую и полностью играбельную игру **«Gem Tower Defense»** на Godot 4. Это рабочее название, кодовое имя проекта — `gem_td`.

Игра оригинальная, но её механика повторяет классическую карту Gem TD для Warcraft III и её наследников (Gem TD+, Gem TD для Dota 2). Механики (draft камней, лабиринт из камней, чекпоинты, рецепты) воспроизводим близко к оригиналу. Ассеты, код, тексты, названия спец-башен и врагов делаем только свои. Базовые гемы называются по реальным минералам (Ruby, Sapphire…), это общие слова, их оставляем. Слова «Gem TD» в названии не используй. Название «Gem Tower Defense» уже занято браузерной игрой, поэтому в отчёте этапа 0 предложи 3 оригинальных названия.

Принципы работы:
1. Сначала играбельный MVP, потом наращивание. Каждый этап заканчивается рабочей сборкой.
2. Мелкие решения принимай сам и записывай в `docs/DECISIONS.md` (решение → причина). Вопросы пользователю задавай только при блокирующей неясности.
3. Проверяй себя запуском Godot из CLI: headless-тесты, бот-прогоны, скриншоты. Без запуска этап не считается готовым.
4. После каждого этапа пиши отчёт по шаблону из §15.

## 1. Что строим

Single-player roguelike tower defense и LAN-мультиплеер в режиме «Гонка».

- Каждый раунд игрок ставит на поле 5 камней, каждый сразу раскрывается в случайный гем (тип + качество).
- Только один гем остаётся боевой башней. Вместо этого его можно улучшить через Combine или превратить в спец-башню. Остальные 4 становятся стенами лабиринта.
- Наземные враги идут кратчайшим путём через 5 чекпоинтов, путь пересчитывается после каждой постройки. Летающие игнорируют лабиринт.
- Игрок собирает рецепты из гемов и создаёт мощные спец-башни.
- Цель — пережить 42 волны. После победы идёт «Испытание урона» для таблицы лидеров.

## 2. Архитектурные инварианты (нарушать нельзя)

1. **Детерминированная симуляция отдельно от визуала.** Вся игровая логика лежит в `sim/`: чистые классы `RefCounted` без зависимости от узлов сцены. Симуляция работает с фиксированным тиком (30 тиков/с, значение в data). Визуал (`view/`) только читает состояние и события симуляции и интерполирует их.
2. **Любое действие игрока — это команда** с номером тика: `PlaceRock`, `KeepGem`, `Combine`, `Forge`, `UpgradeQuality`, `UpgradeTower`, `Sell`, `BreakWall`, `BuyLife`, `SetTargeting`, `StartWave` и т.д. Seed плюс поток команд полностью воспроизводят забег. На этом построены реплеи, сохранения, проверка рекордов, мультиплеер и тесты.
3. **Один источник случайности** — `RunRng`: свой PCG32 или xorshift с явным состоянием, глобальные `randi()`/`randf()` не используются. Нужны именованные под-потоки: `rng.fork("draft", round, slot)`, `rng.fork("combat", wave)` и т.д. Тогда один и тот же seed даёт одни и те же камни, что бы ни происходило в бою.
4. **Все числа баланса лежат в `data/`**: JSON со схемой, валидация при загрузке с понятными ошибками. Магических чисел геймплея в коде нет.
5. **События идут через сигналы/EventBus.** Прямых ссылок между UI и sim нет.
6. **Звук играется только через `Audio.play("event/id")`.** Код не знает путей к файлам (см. §9).
7. **Нереализованных фич в UI нет**: ни заглушек, ни «Coming soon», ни неактивных кнопок без причины. Например, «Продолжить» видна, только если есть сохранение.

## 3. Движок и платформа

- Godot 4.7.x stable. Минимум 4.4: нужны `AudioStream*.load_from_file()` и Metal. Первым делом выполни `godot --version`. Если Godot не найден, предложи установить его (`brew install --cask godot`) и дождись установки.
- macOS Apple Silicon (arm64). Renderer — Forward+ на Metal (`rendering/rendering_device/driver.macos="metal"`), запасной вариант — Vulkan через MoltenVK. Fallback — Compatibility с упрощёнными эффектами; проверь, что в нём игра запускается без ошибок.
- Окно адаптивное: stretch mode `canvas_items`, aspect `expand`, HiDPI/Retina включены. Режимы fullscreen, borderless и windowed, масштаб UI 75–150 %.
- Включи `application/config/use_custom_user_dir=true` и `custom_user_dir_name="GemTowerDefense"`. Тогда `user://` = `~/Library/Application Support/GemTowerDefense/`; это нужно для подмены звуков и поиска сохранений.
- Контент: свои сцены, GDScript, шейдеры, процедурные меши, текстуры и звуки. Из сторонних ассетов допустимы только CC0 (звук, текстуры) и OFL (шрифты с кириллицей). Каждый сторонний файл записан в `assets/LICENSES.md` и показан на экране «Авторы».
- В рантайме нет внешних API, телеметрии, рекламы, облака и аккаунтов. Сеть используется **только** для LAN/direct-IP мультиплеера, который игрок запускает сам.

## 5. Игровой процесс

### 5.1 Поле и маршрут

- Сетка 32×24. Описание карты лежит в `data/maps/arena_01.json`: размер, вход, выход, чекпоинты, запретные клетки, декор. В начале игры поле пустое.
- Маршрут: **Вход → C1 → C2 → C3 → C4 → C5 → Выход (цитадель)**. Враги проходят чекпоинты строго по порядку. Расставь чекпоинты так, чтобы отрезки маршрута пересекались в центре поля: там появляются «горячие зоны», где одна башня бьёт врагов по несколько раз.
- Наземные враги идут кратчайшим путём между соседними точками маршрута через `AStarGrid2D`. Режим диагоналей задаётся в data, по умолчанию диагонали разрешены без срезания углов.
- Летающие враги летят по прямой от точки к точке, игнорируя стены.
- Строить нельзя:
  - на чекпоинтах и в радиусе вокруг них (радиус в data);
  - на входе, выходе и границе поля;
  - так, чтобы любой отрезок маршрута стал недостижим.
  
  Проверка работает и для превью (до клика), и при установке.
- Строить можно только в фазе строительства, поэтому во время волны путь не меняется.
- Превью при наведении:
  - призрак камня;
  - анимированная линия нового пути;
  - изменение длины пути («+6 клеток» зелёным, «−2» красным);
  - причина запрета, например «Перекрывает путь C3 → C4».
  
  В HUD всегда видна текущая длина лабиринта.
- Камера: фиксированный наклон (2.5D), плавный зум колесом. Панорама — WASD, стрелки, средняя кнопка или край экрана (опция). Home сбрасывает камеру.

### 5.2 Фаза строительства — подробный сценарий раунда

1. Появляется баннер «Раунд N · Строительство». В лотке лежат 5 необработанных камней.
2. Игрок ставит камни по одному. Каждый камень **сразу раскрывается** в гем:
   - тип — один из 8, равновероятно, если нет модификаторов;
   - качество — по таблице шансов текущего уровня удачи (§5.5).
   
   Ролл зависит только от `seed + раунд + номер слота`, а не от позиции или времени.
3. Раскрытие — главный «вау-момент» раунда: камень трескается, вспыхивает цветом стихии, поднимается луч, высота которого растёт с качеством. У каждого качества свой звук (`sfx/build/reveal/q1…q5`).
4. После пятого камня выезжает панель выбора (draft) с 5 карточками, привязанными к гемам на поле. Наведение на карточку подсвечивает гем и его радиус на поле, и наоборот.
5. Доступные действия. Неприменимые скрыты, а не показаны серыми.
   - **Keep** — выбранный гем становится башней, остальные 4 превращаются в стены.
   - **Combine ×2** — если среди 5 гемов раунда есть 2 одинаковых (тип + качество), выбранный из них становится на 1 качество выше. Остальные 4 превращаются в стены.
   - **Combine ×4** — 4 одинаковых гема дают +2 качества. Выше V качество не поднимается; если результат упрётся в потолок, Combine недоступен.
   - **Forge (one-hit)** — если 5 гемов раунда содержат полный рецепт спец-башни, выбранный компонент превращается в спец-башню.
   - **Forge (из коллекции)** — если оставленный гем вместе с башнями прошлых раундов закрывает рецепт, на гем ставится кнопка «Сплавить». Использованные башни на поле превращаются в стены, лабиринт не ломается. Кнопка доступна в любой фазе строительства, пока все компоненты стоят на поле.
6. До подтверждения игрок видит полный превью результата: какие клетки станут стенами, итоговый путь, характеристики новой башни и сравнение с текущими башнями.
7. Подтверждение (Space): 4 гема кристаллизуются в обсидиановые стены (пыль, звук). Затем показывается превью следующей волны и отсчёт 3-2-1, который можно пропустить пробелом.
8. В фазе строительства за золото доступно:
   - **Upgrade Quality**;
   - улучшение спец-башен;
   - **Разбить стену** — стоимость растёт, значения в data, проверка пути обязательна;
   - **Купить жизнь** — до максимума;
   - **Продать башню** — башня становится стеной, игрок получает её стоимость × коэффициент.

Склада камней нет. Компоненты рецепта собираются так: в разных раундах игрок оставляет нужные гемы на поле через Keep. В этом главное напряжение оригинала: каждый Keep — выбор между силой сейчас и рецептом потом.

### 5.3 Фаза атаки

- Волна выходит из входа, спавн идёт по таблице волны. Автостарт следующей волны включается в настройках.
- Башни атакуют сами. Приоритет цели выбирается в панели башни:
  - первый к выходу по прогрессу пути (по умолчанию);
  - последний;
  - самый сильный;
  - самый слабый;
  - сначала летающие.
  
  Кнопка «Стоп» выключает атаку башни; это нужно для управления MVP, как в оригинале.
- Цели ищутся через пространственный хеш по клеткам, физический движок не используется.
- Скорость 1×/2×/4× — это больше тиков симуляции за кадр (с верхним пределом). Пауза — 0 тиков.
- Когда враг доходит до выхода, игрок теряет жизни: значение задано у типа врага (обычный 1, элита 2, босс — по data). На цитадели появляется трещина, в журнал пишется событие.
- Конец волны: бонус золота и отдельный бонус за «чистую» волну без утечек, награда MVP, автосохранение, переход к строительству.

### 5.4 MVP

Башня, нанёсшая больше всех урона за волну, получает стак MVP: +X % урона за стак, максимум 10. На 10 стаках башня получает ауру +Y % урона для соседей в радиусе 2 клеток. Значения в data. Над башней видны пипсы-короны.

### 5.5 Качество гемов и шансы

5 уровней качества со своими названиями: **I Shard (Осколок) · II Rough (Сырой) · III Cut (Огранённый) · IV Radiant (Сияющий) · V Prismatic (Призматический)**. Число уровней и названия задаются в `data/qualities.json`; если нужно, их можно сократить до 3.

Upgrade Quality — 9 уровней удачи. Стартовая таблица шансов в процентах взята из Gem TD+ 1.5.4; менять её только через data:

| Удача | I | II | III | IV | V |
|---|---|---|---|---|---|
| 1 | 100 | 0 | 0 | 0 | 0 |
| 2 | 70 | 30 | 0 | 0 | 0 |
| 3 | 60 | 30 | 10 | 0 | 0 |
| 4 | 50 | 30 | 20 | 0 | 0 |
| 5 | 40 | 30 | 20 | 10 | 0 |
| 6 | 30 | 30 | 30 | 10 | 0 |
| 7 | 20 | 30 | 30 | 20 | 0 |
| 8 | 10 | 30 | 30 | 30 | 0 |
| 9 | 0 | 30 | 30 | 30 | 10 |

Стоимость уровней задаётся растущей кривой в `economy.json`. В тултипе предупреди, что высокая удача мешает собирать рецепты из низких качеств.

### 5.6 Экономика

- **Доходы:** награда за убийство (тип врага × множитель волны × сложность), бонус за волну, бонус за чистую волну, эффекты Opal и Gilded Idol.
- **Расходы:** Upgrade Quality, улучшения спец-башен, разрушение стен, покупка жизней.
- **Продажа:** башня становится стеной, игрок получает (базовая стоимость по качеству или спец-башне + вложенные улучшения) × коэффициент.
- Баланс должен поддерживать 5 стратегий:
  1. ранний длинный лабиринт и дешёвые башни;
  2. экономия ради ранних спец-башен;
  3. агрессивный урон;
  4. контроль и замедление;
  5. упор в анти-воздух.
  
  Это проверяется через `tools/balance_sim.gd` (§14).

### 5.7 Жизни, сложность, поражение

- Сложности: Easy, Normal, Hard, Extreme. Стартовые и максимальные жизни, множители HP, награды и очков лежат в `difficulty.json`. Как и в Gem TD+, сложность масштабирует в первую очередь HP врагов.
- 0 жизней означает поражение. Утечка босса стоит отдельного количества жизней; на Extreme она означает мгновенное поражение.

## 6. Контент

### 6.1 Базовые гемы (8 типов × 5 качеств)

Цвет = тип урона, форма = роль. Цели: G — наземные, A — воздушные.

| Гем | Роль | Урон | Цели | Механика (растёт с качеством) | Силуэт башни |
|---|---|---|---|---|---|
| Ruby | высокий урон по одной цели | fire | G+A | медленные мощные выстрелы; на V каждая 4-я атака ×3 | высокая игла |
| Sapphire | цепная молния | arcane | G+A | прыгает на 2→6 целей с затуханием | спираль-катушка |
| Emerald | яд, урон со временем | nature | G+A | стаки яда; яд режет регенерацию; на V яд переходит на соседа при смерти | бутон |
| Topaz | урон по площади | siege | G | взрыв радиусом 1→2 клетки | приземистая мортира |
| Amethyst | анти-воздух, быстрые атаки | pierce | G+A | ×1.5→×2.5 по воздушным, высокая скорострельность | кристалл-копьё |
| Aquamarine | замедление | frost | G+A | −15→−40 % скорости (на боссов вдвое слабее) | кольцо-ореол |
| Opal | поддержка, золото | arcane | G+A | аура скорости атаки соседям, обнаружение невидимых; на IV–V +золото за убийства рядом | парящая линза |
| Diamond | крит и пробитие брони | physical | G | крит 10→25 %, игнор брони 2→10 | октаэдр |

Числа (урон, дальность в клетках, атак/с, параметры эффектов) лежат в `gems.json`. Ориентир масштабирования: урон примерно ×2 за уровень качества, эффект заметно растёт, у качества V есть «подписная» способность.

### 6.2 Спец-башни (13)

Рецепт — 3 базовых гема точно указанного типа и качества. Рецепты намеренно отличаются от оригинала, но повторяют его кривую: ранние собираются из I–II, средние из II–III, поздние из IV–V.

У каждой спец-башни 3 уровня:
- L2 покупается за золото;
- L3 стоит золото + 1 гем текущего раунда указанного типа с качеством не ниже указанного; этот гем выбирается вместо Keep.

`forge_cost` лежит в data, у ранних башен он равен 0. Если гем подходит к нескольким рецептам, UI предлагает выбор.

| Спец-башня (роль) | Рецепт | Урон · дальн. · атак/с | Эффект L1 | L2 | L3 (+гем) |
|---|---|---|---|---|---|
| **Beacon Lens** (поддержка, дальность) | Opal I + Amethyst I + Aquamarine I | arcane · аура 2.5 · — | соседи: +1 клетка дальности, +10 % скорости атаки | +1.5 / +15 % | +2 / +20 %, видит невидимых (Opal III) |
| **Cinder Crown** (урон по площади) | Ruby I + Topaz I + Emerald I | fire · аура 2.5 · 2 тика | жжёт всех врагов в радиусе | радиус 3, урон ×2.5 | раз в 5 с вспышка ×10 (Ruby IV) |
| **Skypiercer** (анти-воздух) | Amethyst II + Sapphire I + Diamond I | pierce · 6 · 2.0 | ×3 по воздушным, ×0.5 по наземным | пробивает 2 воздушные цели | цель −30 % скорости и +20 % получаемого урона (Amethyst IV) |

### 6.3 Типы урона и брони

- Типы урона (8): physical, pierce, siege, fire, frost, nature, arcane, pure.
- Типы брони (7): unarmored, light, medium, heavy, fortified, ethereal, boss.
- Матрица множителей 8×7 лежит в `damage_matrix.json`, значения 0.5–1.75. Урон типа pure всегда даёт ×1.0 и игнорирует броню.
- Число брони снижает урон по формуле из data. Отрицательная броня урон увеличивает.
- В тултипах показывай, против кого гем эффективен в следующей волне.

### 6.4 Враги

- **Архетипы:** Normal, Fast, Armored, Arcane-resistant, Flying, Swarm, Regenerating, Shielded, Splitter (при смерти раскалывается на 2–4 малых), Boss.
- **Параметры:** HP, скорость, тип и значение брони, награда, сопротивления, урон по жизням при утечке, размер, трейты.

Трейты появляются постепенно, с 8-й волны. В поздних волнах у врагов по 2–3 трейта.

| Трейт | Эффект | Контрплей |

| Рывок | при HP < 50 % скорость ×2 на 2 с | замедление, оглушение |
| Мерцание | раз в 6 с телепорт на 3 клетки вперёд по пути | длинный лабиринт, урон в конце пути |
| Регенерация | +X % HP в секунду | яд Emerald режет лечение |
| Уклонение | 20 % промахов по physical/pierce | arcane, яд, урон по площади |
| Антимагия | иммунитет к arcane и контролю | physical, siege |
| Эфирность | иммунитет к physical | arcane, fire, nature |
| Отражение | поглощает первые N попаданий | скорострельные башни, Rust Obelisk L3 |
| Закалка | +1 броня за каждые K попаданий (есть предел) | редкие мощные удары, снижение брони |

| Покров | невидим вне радиуса обнаружения (Opal, Beacon Lens L3) | Opal в лабиринте |

### 6.5 Волны (42)

- **Каждая 4-я волна (4, 8, …, 40) полностью воздушная.** Лабиринт против неё не работает, в этом ключевое напряжение оригинала.
- **Боссы:**
  - 10 — наземный;
  - 20 — летающий (совпадает с воздушной волной);
  - 30 — наземный, с эскортом и призывом миньонов;
  - 42 — финальный, 3 фазы: щит → ярость и ускорение → призыв наземного и воздушного эскорта.
- **Модификаторы волн:** armored, swarm, elite (меньше врагов, ×HP, трейты), boss escort, rush, mixed.

| Волны | Содержание |
|---|---|
| 1–3 | normal и fast без трейтов (обучение) |
| 4 | первая воздушная, лёгкая |

| 21–29 | Закалка, Антимагия/Эфирность, Отражение, elite-волны; воздушные 24 и 28 |

## 7. Графика и VFX

- **2.5D:** 3D-сцена, камера под углом ~55°. Перспектива с малым FOV или ортографическая камера — выбери по читаемости и запиши в DECISIONS. Поле собрано из рунических плит.
- **Стиль:** тёмный фэнтези-минимализм.
  - Обсидиановая арена и светящиеся самоцветы.
  - Чекпоинты — рунические платформы с номерами.
  - На входе портал.
  - На выходе цитадель-кристалл: она трескается и тускнеет по мере потери жизней.
- **Гемы:** процедурные огранённые меши (ArrayMesh/SurfaceTool). Шейдер даёт френель и rim light цвета стихии, пульсирующее внутреннее свечение, фейковое преломление (screen texture) и блики. Качество читается визуально: размер, число граней, яркость, частицы вокруг V.
- **Башни:** цвет = тип урона, силуэт = роль. Спец-башни заметно крупнее, у каждой уникальный силуэт, idle-анимация, свой источник света и частицы.
- **Враги:**
  - стилизованные low-poly силуэты по архетипам;
  - рендер через `MultiMeshInstance3D` с данными на каждый экземпляр (цвет, вспышка попадания, dissolve);
  - летающие висят над землёй и отбрасывают на неё тень;
  - HP-бары появляются при получении урона, Alt показывает все;
  - иконки статусов: яд, замедление, оглушение, снижение брони.
- **Снаряды:** светящиеся, со следом; пул объектов или MultiMesh.
- **Шейдеры:**
  - пульсация гемов;
  - энергетические снаряды;
  - dissolve при смерти;
  - ударные волны с искажением;
  - яд, иней замедления, руны оглушения;
  - вспышка крита;
  - бегущие штрихи на линии пути.
- **Частицы (GPUParticles3D):**
  - искры при попадании;
  - осколки при смерти;
  - следы снарядов;
  - пыль при появлении стены;
  - взрыв цвета при раскрытии гема;
  - вихрь при Combine и Forge.
- **Пост-обработка:** glow (bloom), тонмаппинг AgX или ACES, мягкое тонирование, виньетка. Хроматическая аберрация и лёгкая тряска — только на боссах и крупных взрывах. SSAO и туман — в высоких пресетах.
- **Анимации:**
  - появление башни — подъём из плиты со вспышкой;
  - атака — отдача или заряд;
  - получение урона — вспышка;
  - смерть — dissolve и осколки;
  - Combine — гемы слетаются, сливаются, ударная волна;
  - Forge — руны рецепта соединяются лучами, вспышка, короткий кинематографичный зум (отключаемый).
- **Пресеты графики** Low, Medium, High, Ultra: glow, SSAO, плотность частиц, MSAA/TAA, масштаб рендера, тени.

## 8. UI/UX

### 8.1 Визуальное направление

Тёмный «стеклянный» интерфейс поверх обсидиановой арены. Панели полупрозрачные, с размытием фона (BackBufferCopy + blur-шейдер), тонкими светящимися границами и акцентами цветом стихий. Минимализм: подробности показываются по наведению или удержанию клавиши, а не висят постоянно.

### 8.2 Дизайн-система (обязательна)

- **Токены в одном месте** (`ui/theme/tokens.gd` + `theme.tres`):
  - палитра: фон, поверхности, 3 уровня текста, акцент, success/warning/danger, 8 цветов стихий и варианты для дальтоников;
  - типографика: шкала 12/14/16/20/28/40, табличные цифры для статов;
  - отступы 4/8/12/16/24/32;
  - радиусы 6/10/16;
  - тени и свечения;
  - моушен: fast 120 мс, base 200 мс, slow 350 мс; easing out-expo для появления, out-back для «поп»-эффектов.
- **Переиспользуемые компоненты:** Button (primary/secondary/ghost/danger), Card, GemCard, Tooltip (rich text, ключевые слова ведут в глоссарий), Modal, Toast, Badge, StatRow со стрелкой изменения, Meter, Tabs, HotkeyHint.
- Захардкоженных цветов и шрифтов в сценах нет.
- Шрифты OFL с кириллицей: например, Inter или Manrope для UI и цифр, Cormorant или Forum для заголовков.

### 8.3 Экраны

- **Главное меню:** живой фон (гемы медленно вращаются над ареной, параллакс), название с shimmer-шейдером. Пункты: Новая игра, Продолжить (только если есть сейв), Мультиплеер, Таблица лидеров, Кодекс, Настройки, Авторы, Выход.
- **Новая игра:**
  - карточки сложности с описанием и множителем очков;
  - seed: случайный, «Seed дня» или свой, кнопка «Скопировать»;
  - переключатель обучения.
- **HUD:**


- **Карточки draft:**
  - иконка и пипсы качества;
  - роль и ключевые статы;
  - оценка DPS против следующей волны;
  - «Входит в рецепт: Frostwell (2/3)» с подсветкой недостающих частей;

- **Панель башни:**
  - статы;
  - урон за волну и за всю игру, убийства, стаки MVP;

  - волна, убийства, золото;

  - использованные спец-башни;

### 8.4 Анимации и «сочность»

- Переходы между экранами: шейдерный dissolve или кристаллизация, 300–400 мс.
- Списки появляются со сдвигом 30–40 мс между элементами.
- Hover: карточка приподнимается, светится, звучит тихий звук. Нажатие: сжатие до 0.96.
- Раскрытие гема: трещины → вспышка → луч. Для IV–V время замедляется на 0.2 с и звучит отдельный звук.
- Золото: монеты летят к счётчику, счётчик «тикает».
- Потеря жизни: пульс красной виньетки, дрожание сердца, трещина на цитадели.
- Баннер волны проезжает полосой с названием и модификатором.
- Босс: затемнение, крупное имя, полоса HP сверху с отметками фаз.
- Числа урона: из пула, цвет по типу урона, криты крупнее. При большой плотности числа агрегируются; их можно отключить.
- Всё сделано на Tween/AnimationPlayer и учитывает настройку «Уменьшить анимации».

### 8.5 UX-правила

## 9. Аудио: подмена звуков без пересборки

### 9.1 Принцип

**Одно звуковое событие — одна папка.** Все аудиофайлы в папке — варианты события; играется случайный, без повтора подряд. Чтобы заменить звук, достаточно положить свои файлы в такую же папку в каталоге-оверрайде. Пересобирать игру и открывать Godot не нужно.

### 9.2 Структура

Так устроен встроенный пак `res://audio/`, и так же — любой оверрайд.

```
audio/
  audio_manifest.json      # события, шины, громкость по умолчанию, fallback
  sfx/
    ui/        hover/ click/ confirm/ cancel/ error/ panel_open/ panel_close/ toast/ tab_switch/
    build/     rock_place/ invalid/ reveal/q1/ … reveal/q5/ wall_form/ wall_break/ path_change/
    choose/    keep/ combine_x2/ combine_x4/ forge_onehit/ forge_collect/
    gems/      ruby/ sapphire/ emerald/ topaz/ amethyst/ aquamarine/ opal/ diamond/
                 └─ каждый: attack/ impact/
    specials/  <special_id>/attack/ impact/ ability/ upgrade/
    status/    poison_tick/ slow_apply/ stun/ crit/ armor_break/
    enemies/   <archetype>/spawn/ hurt/ death/
    traits/    <trait_id>/
    boss/      warning/ spawn/ phase_change/ death/
    waves/     start/ clear/ perfect/ air_warning/ countdown/
    economy/   gold_gain/ quality_up/ sell/ buy_life/ mvp/
    game/      life_lost/ victory/ defeat/ new_record/
    net/       player_joined/ player_left/ ready/ opponent_eliminated/ match_start/
  music/       menu/ build/ combat/ boss/ victory/ defeat/
  ambience/    arena/
```

### 9.3 Порядок поиска

Для каждого события выигрывает первый непустой источник:

1. `--audio-dir=<путь>` — аргумент командной строки;
2. `<папка рядом с .app>/audio_override/` — портативный режим, подпись .app не ломается;
3. `user://sound_packs/<активный пак>/` — пак выбирается в настройках, по умолчанию `custom`;
4. встроенный `res://audio/`.

По умолчанию файлы оверрайда **заменяют** встроенные. Если в папке есть `_event.json` с `"mode": "append"`, они добавляются к встроенным.

### 9.4 Детали

- **Форматы:** `.ogg`, `.wav`, `.mp3`.
  - Внешние файлы загружаются через `AudioStreamOggVorbis/WAV/MP3.load_from_file()`.
  - Встроенные — обычные импортированные ресурсы: в экспортированной сборке `load_from_file` для `res://` не работает.
- **`_event.json`** в папке события (необязателен): `volume_db`, `pitch_jitter`, `cooldown_ms`, `max_voices`, `bus`, `loop`, `mode`. Он важнее значений из манифеста.
- **`audio_manifest.json`:**
  - id всех событий и шина (Master, Music, SFX, UI, Ambience);
  - параметры по умолчанию;
  - `fallback`, чтобы игра никогда не молчала. Например, `specials/stormspire/attack` → `gems/sapphire/attack`.
- **Полифония:** ограничение одновременных звуков и антиспам (`max_voices`, `cooldown_ms`) обязательны, иначе 200+ врагов превратят звук в шум.
- **Пространство:** боевые звуки слегка панорамируются по позиции на поле, звуки UI — нет.
- **Музыка:** состояния menu, build, combat, boss, victory, defeat с кроссфейдом 1–2 с.
- **Первый запуск:** игра создаёт `user://sound_packs/custom/` с полным деревом пустых папок и `README.txt`: как заменить звук, какие форматы подходят, список событий.
- **Настройки → Аудио:**
  - громкость по шинам;
  - выбор пака;
  - кнопка «Открыть папку звуков» (`OS.shell_open`);
  - кнопка «Перезагрузить звуки» — горячая перезагрузка без рестарта;
  - звуковой браузер: все события, их источник (override или default) и кнопка ▶.
- **Отчёт:** `godot --headless --path . -- --audio-report` печатает таблицу событий: источник, число файлов, пропуски.
- **Звуки по умолчанию:** процедурные, через `tools/sfx_generator.gd` (синтез в духе sfxr → `AudioStreamWAV.save_to_wav`), и/или CC0. Каждое событие из манифеста озвучено, молчащих нет.
- `docs/AUDIO_MODDING.md` — инструкция для игрока.

## 10. Таблица лидеров, реплеи, рекорды

### 10.1 Хранение

- Локальные профили игроков (имя, цвет, UUID) лежат в `user://profiles/`.
- Таблица лидеров — `user://leaderboard.json`:
  - схема с версией и миграциями;
  - атомарная запись через временный файл;
  - резервная копия.
- Реплеи — `user://replays/<id>.gtdr`. Внутри:
  - версия игры и хеш data;
  - seed, сложность, режим;
  - лог команд с тиками;
  - контрольные суммы состояния каждые N волн и итоговая контрольная сумма.

### 10.2 Категории (вкладки)

| Категория | Метрика | Примечание |
|---|---|---|
| Классика | очки по формуле из `scoring.json` | отдельно по сложностям |
| Скорость | суммарное время боевых фаз до победы над 42-й волной, меньше — лучше | аналог «Time» из Gem TD+; считается в тиках симуляции, поэтому не зависит от 1×/4× и от времени на раздумья |
| Испытание урона | средний DPS | аналог «DPS» (Damage Test) из Gem TD+ |
| Seed дня | очки на seed, вычисленном из даты (оффлайн) | в таблицу идёт лучшая попытка за день |
| Гонка | победы, места, среднее место в LAN-матчах | плюс история матчей |

Фильтры: сложность, версия игры, профиль или все.

### 10.3 Запись

Поля записи:
- место, имя, метрика, исход, пройденные волны;
- сложность, seed, дата;
- время симуляции и реальное время;
- убийства и утечки;
- лучшая башня и использованные спец-башни (иконками);
- общий урон и пиковый DPS;
- версия игры и флаг «проверено».

Пример формулы очков (точные коэффициенты — в `scoring.json`):
`очки = Σ(100 × номер пройденной волны + 50 за чистую волну) + убийства + 250 × оставшиеся жизни + бонус за скорость`, всё умножается на множитель сложности.

### 10.4 Честность

- **Проверка:** после партии реплей в фоне пересимулируется headless (отдельный поток или процесс). Если контрольная сумма совпала, запись помечается «✓ проверено».
- **Обмен:** результат можно экспортировать вместе с реплеем (`.gtdr`) и отправить друзьям. Импортированный результат принимается только после успешной пересимуляции.
- **Онлайн-таблицы** в этой версии нет: серверов нет. `Leaderboard` спроектирован через интерфейс провайдера, но реализован только локальный провайдер, фейковых «онлайн»-кнопок нет.

### 10.5 UX

- Анимация «Новый рекорд! #3 · Классика / Hard» и разница с личным рекордом.
- Ввод имени (последнее запоминается), своя строка подсвечена.
- Раскрывающаяся карточка записи:
  - сводка билда;
  - «Смотреть реплей» — просмотр на 1–8× с перемоткой по волнам;
  - «Скопировать seed»;
  - «Сыграть этот seed».

## 11. Мультиплеер «Гонка» (LAN / direct IP) — первая итерация

### 11.1 Режим

- 2–4 игрока. У каждого своё поле на одной карте, общий seed и одинаковые волны.
- Побеждает последний выживший. Если 42-ю волну прошли несколько игроков, они ранжируются по оставшимся жизням, затем по очкам, затем по времени симуляции.
- **«Честные камни»** (включено по умолчанию): роллы камней у всех одинаковые (`seed + раунд + слот`). Различаются они только из-за разного уровня удачи, так что побеждает решение, а не рандом.

### 11.2 Синхронизация (простая и надёжная)

- Высокоуровневый мультиплеер Godot + `ENetMultiplayerPeer`, порт по умолчанию 7777 (настраивается). Хост отвечает за лобби и тайминги и при этом сам играет.
- Каждый клиент симулирует **своё** поле локально (симуляция детерминирована). По сети передаются только:
  - команды игрока — для наблюдения и проверки;
  - готовность и стадия раунда;
  - сводки состояния 2–5 раз в секунду: жизни, волна, золото, урон, длина лабиринта;
  - контрольная сумма в конце волны.
- **Раунды синхронны.**
  - Фаза строительства идёт с таймером: 45, 60 или 90 с либо без лимита — выбирает хост.
  - Волна стартует у всех одновременно, когда все готовы или вышел таймер. Не поставленные камни ставятся автоматически по правилу из data.
  - Скорость матча (1× или 2×) задаёт хост. Паузу ставит только хост, ограниченное число раз.
- **Наблюдение.** Панель соперников показывает имя, цвет, жизни, волну, DPS и мини-карту лабиринта после каждой фазы строительства. По клику включается наблюдение за полем соперника: оно воспроизводится локально из его команд. Выбывший игрок автоматически становится наблюдателем.

### 11.3 Лобби и подключение

- **Хост задаёт:** имя матча, seed, сложность, таймер, «честные камни», максимум игроков.
- **Клиент видит:**
  - список LAN-игр — хосты раз в секунду рассылают UDP-маячок на порт 7778;
  - ручной ввод IP:порт;
  - кнопку «Скопировать мой IP», которая показывает локальные адреса.
- **Рукопожатие** сверяет версию игры и хеш data. При несовпадении игрок видит понятную ошибку.
- **В лобби:** слоты игроков с цветами, готовность, кик (у хоста), короткий чат и быстрые пинги.
- **Отключение:**
  - если отключился клиент, он выбывает, его результат фиксируется;
  - если отключился хост, матч завершается с понятным сообщением, результаты сохраняются.
  
  Переподключение — во второй итерации, в UI его нет.
- **macOS:** при первом хостинге система спросит про входящие соединения и доступ к локальной сети. Опиши это в README и при необходимости добавь в экспорт `NSLocalNetworkUsageDescription`.
- Результаты матча пишутся в лидерборд каждого игрока (вкладка «Гонка») вместе с реплеем матча.

### 11.4 Тестирование мультиплеера

- Аргументы запуска: `-- --mp-host --name=A --bot` и `-- --mp-join=127.0.0.1 --name=B --bot`.
- Автотест: два headless-процесса с ботами проходят 5 волн. Оба должны получить итоговую таблицу, а их контрольные суммы — совпасть с одиночной пересимуляцией.

### 11.5 Вне первой итерации

Только описать в `docs/NETCODE.md`, в UI не показывать: кооператив на общем поле, переподключение, игра через интернет (relay или WebRTC), «давление» на соперников.

Режим «Призрак» — гонка с реплеем своего лучшего забега — сделай на этапе 3, если останется время: благодаря реплеям он почти бесплатный.

## 12. Сохранения и настройки

- **Сейв** = seed + лог команд + снимок состояния на начало фазы строительства (для быстрой загрузки) + версия.
  - Автосейв в начале каждой фазы строительства и 3 ручных слота.
  - При загрузке проверяются версия и хеш data; при несовместимости — понятная ошибка.
  - В мультиплеере сейвов нет.
- **Настройки** лежат в `user://settings.cfg`:
  - графика: пресет, режим окна, vsync, лимит FPS, масштаб рендера, масштаб UI;
  - аудио: см. §9;
  - геймплей: автостарт волн, числа урона, тряска, «уменьшить анимации», подтверждения;
  - управление: переназначение клавиш;
  - язык и доступность.

## 13. Производительность

- **Цели:**
  - стабильные 60 FPS на M1 при 250 врагах, 60 башнях и скорости 4× (пресет High);
  - один тик симуляции укладывается в 2 мс при 300 врагах.

  - MultiMesh для врагов и снарядов;
  - пулы объектов для снарядов, частиц и чисел урона;

  - кеш путей — пересчёт только при изменении поля.
- **Стресс-тест** `tests/perf/stress.tscn`: 300 врагов и 60 башен в течение 60 с. Средний FPS, 1 % low и время тика записываются в `docs/perf.md`.

## 14. Тестирование и самопроверка

- **Тестовый раннер:** GUT (MIT) или свой минимальный раннер без зависимостей. Все тесты запускаются одной командой `godot --headless --path . -s res://tests/run_all.gd`; при провале код выхода ненулевой.
- **Обязательные тесты:**

| Область | Что проверить |
|---|---|
| RNG | воспроизводимость, независимость под-потоков |
| Поле и пути | маршрут через все чекпоинты, запрет блокировки, летающие |
| Фаза строительства | 5 камней, роллы по seed |
| Combine | ×2 и ×4 |
| Рецепты | one-hit, из коллекции, несколько рецептов одновременно |
| Урон | матрица, броня, криты, статусы, стаки |
| Волны | прогрессия, боссы, воздушные каждую 4-ю |
| Экономика и очки | расчёты экономики и scoring |
| Сейвы | сохранение → загрузка без потерь |
| Реплеи | пересимуляция даёт ту же контрольную сумму |
| Аудио | порядок поиска, fallback, `append`/`replace` |
| Сеть | сериализация сообщений протокола |

- **Бот-прогон:** `-- --autoplay --seed=42 --waves=10 --strategy=maze`. Бот играет сам и печатает итог и контрольную сумму. Два прогона подряд обязаны совпасть.
- **Баланс:** `tools/balance_sim.gd` гоняет 5 стратегий на 50 seed и пишет CSV: до какой волны дошли, процент побед, золото, урон по типам. Ни одна стратегия не должна доминировать или быть бесполезной; критерий запиши в DECISIONS.
- **Скриншоты:** `-- --screenshot=<scene>` сохраняет PNG в `docs/screenshots/`. Нужны: меню, фаза строительства, draft, бой с 200 врагами, босс, лидерборд, лобби. Просматривай их сам и исправляй визуальные проблемы до отчёта.
- При запуске и прогоне в выводе нет ни ошибок, ни предупреждений.

## Приложение A. Как устроен оригинал (для понимания, не для копирования)

- **Строительство:** 5 камней за раунд, каждый становится случайным гемом. Один остаётся, остальные превращаются в камни лабиринта. В Dota-версии есть варианты:
  - Keep;
  - Remove — убрать камень;
  - Merge ^ — +1 уровень;
  - Merge ^^ — +2 уровня;
  - Combine — собрать спец-башню;
  - Downgrade — понизить качество за 200 золота.
- **Качества:** Chipped, Flawed, Normal, Flawless, Perfect; в Gem TD+ есть ещё Great, в Dota-версии — 6-й уровень. Шансы — в таблице §5.5.
- **Спец-башни** собираются либо «one-hit» из 5 гемов одного раунда, либо из частей, накопленных за несколько раундов. После фазы строительства игра проверяет, все ли части собраны, и показывает кнопку на последнем геме.
- **Рецепты Gem TD+ 1.5.4** — образец структуры и кривой сложности (I = Chipped … V = Perfect):

| Спец-башня | Рецепт |
|---|---|
| Malachite | Aquamarine I + Emerald I + Opal I |
| Silver | Diamond I + Sapphire I + Topaz I |
| Star Ruby | Ruby II + Ruby I + Amethyst I |
| Jade | Emerald III + Opal III + Sapphire II |
| Red Crystal | Emerald IV + Ruby III + Amethyst II |
| Dark Emerald | Emerald V + Sapphire IV + Topaz II |
| Gold | Amethyst V + Amethyst IV + Diamond II |
| Uranium | Topaz V + Sapphire III + Opal II |
| Pink Diamond | Diamond V + Diamond III + Topaz III |
| Paraiba Tourmaline | Aquamarine V + Opal IV + Aquamarine II + Emerald II |
| Black Opal | Opal V + Diamond IV + Aquamarine III |
| Bloodstone | Ruby V + Aquamarine IV + Amethyst III |
| Yellow Sapphire | Sapphire V + Ruby IV + Topaz IV |

  Ещё есть секретная башня из всех 8 гемов Perfect и «плиты» (slates). Они вне рамок этой версии.
- **Dota-версия:** спец-башни улучшаются цепочками до 4 ступеней (Basic → Intermediate → Advanced → Top). К башне добавляются гемы определённого качества или другие спец-башни.
- **Маршрут:** старт, 5–6 чекпоинтов, выход. Наземные враги идут кратчайшим путём между чекпоинтами по порядку. Воздушные игнорируют лабиринт и в WC3-версии приходят каждые 4 уровня. В Dota-версии 50 волн с боссом каждую 10-ю, после 50-й волны повторяются с новыми способностями.
- **Способности врагов (Dota):** невидимость, уклонение, обезоруживание, отражение, иммунитет к магии или физике, вор, рывок, мерцание, регенерация, реактивная броня, панцирь, подзарядка.
- **MVP (Dota):** башня с максимальным уроном за волну получает +10 % урона. После 10 наград у неё появляется аура +75 % урона для соседей.
- **Gem TD+:**
  - матрица 7 типов урона × 8 типов брони;
  - Extra Chance — платное повышение шанса выбранного гема; бонус растёт, если цель не выпала;
  - лидерборды «Time» (время на момент прохождения 50-го уровня) и «DPS» (Damage Test); заявка принимается только с реплеем и скриншотом.
- **BK's Gem TD (WC3):** 42 уровня, 8 базовых и 13 спец-гемов — отсюда параметры этой версии.
- **Dota-версия:** 1–4 игрока, рейтинги Solo/Co-op и Race.
